# 使用说明

## 一、启动

```powershell
cd "D:\c++\绳索机器人"
node server.mjs 18000
```

浏览器打开 **http://127.0.0.1:18000/web/index.html**

（服务器是零依赖的 Node 脚本，只用于静态托管、参数读写、以及把固件仿真进程的输出转发给页面。）

## 二、看什么

### 三维视图（左）

| 元素 | 含义 |
| --- | --- |
| 灰色框架 | 按 `新框架/` SolidWorks 装配体搭的四层机架 |
| 黄色圆柱 | 8 个卷筒（上组 4 个在 1.10 m，下组 4 个在 0.90 m） |
| 深灰方块 + 银色减速器 | 86 闭环步进电机 + 减速器 |
| 橙色板 | 动平台（上层橙板 + 下层银板） |
| **彩色连线** | **8 根绳，颜色 = 张力**（蓝低 → 绿中 → 红高） |
| 青色线框 | 目标位姿 |
| 红/蓝小方块 | 平台上的 8 个系绳点（红=上绳，蓝=下绳） |

鼠标：左键拖拽旋转、Shift+左键或右键拖拽平移、滚轮缩放。
右上角「等轴/正面/侧面/俯视」是预设视角。

勾选「张力矢量」会在每个系绳点画出该绳的拉力方向，长度正比于张力大小。

### 左上 HUD

```
位姿 x=... y=... z=... | r=... p=... yaw=...     ← 平台实际位姿
目标 x=... y=... z=... | r=... p=... yaw=...     ← 轨迹目标
力封闭 张力分配可行（Tmin=4.3 N）                  ← 关键判据
```

**`Tmin` 是最小绳张力**。一旦显示「不可行」或 `Tmin` 接近 0，
说明有绳在松弛——这时平台会失去约束，必须降速或调整轨迹。

### 底部三块

1. **绳长曲线**（左）：8 根绳的实时长度，能看到圆轨迹时的正弦变化；
2. **张力曲线**（中）：8 根绳的实时张力；
3. **逐轴状态表**（右）：每根绳的张力、目标张力、当前绳长、卷筒脉冲数、电机转速、电流、状态。

## 三、操作

### 预设位姿

`home / left / right / front / back / up / down / tilt_x / tilt_y / yaw / corner`
点击后平台平滑移动过去（五次多项式，起止速度、加速度为零）。

### 轨迹

- **圆轨迹 + 姿态**：XY 画圆 + Z 起伏 + 俯仰/偏航摆动，周期 10 s；
- **码垛取放**：4 个工位循环，取料 → 抬升 → 转运 → 放料；
- **原地保持**：停在当前位置。

### 仿真倍率

0.25× ~ 4×。注意：倍率只改变仿真推进速度，不改变控制器参数。

### 附加负载

给平台加 0~10 kg 配重，可以观察张力如何随负载变化（这是验证张力分配是否正确的直观方法）。

### 张力分配模式

| 选项 | 什么时候用 |
| --- | --- |
| **非负最小二乘（默认）** | 正常仿真，物理正确（绳只能拉） |
| 最小范数解 | 数学参考：会给出负张力，仅用于对比 |
| 神经启发式 | 对比用：在最小范数解上叠加对抗预紧 |
| 无张力 | 自检：绳不产生力，平台会掉下去 |

## 四、两种数据源

右上角「数据源」下拉框：

### JS 仿真（默认，快）

浏览器 Worker 里跑 2 kHz 物理 + 1 kHz 控制器。
改 `sim/core/*.js` 后刷新页面即生效。**调参数、看现象用这个。**

### STM32 固件 · 无板仿真（真实代码）

页面通过 WebSocket 驱动 `firmware/build/board_sim.exe`——**这是将来烧进
STM32F407 的同一份 C 代码**，只是在 PC 上跑。

用之前先编译一次：

```powershell
cd firmware
build_sim.cmd        # MSVC
# 或
mingw32-make         # MinGW
```

切换后控制台会打印：

```
[固件] 固件就绪（1000 Hz，8 轴）
[固件] circle ok
```

此时三维视图、绳长/张力曲线全部来自固件的输出。**这是验证「你写的控制代码
在真实控制器上会怎么动」的方式**——不用买板子、不用接线。

## 五、改代码

### 改控制律（推荐入口）

`sim/core/controller.js` 的 `Controller.step()`，改完刷新页面。

### 改张力分配

`sim/core/core.js` 的 `allocateT()`，或加一个新的 mode。

### 改轨迹

`sim/core/trajectory.js`。

### 改固件（会烧到板子上）

`firmware/core/cdpr_core.c`（控制核心）、`firmware/core/cdpr_traj.c`（轨迹）。
改完 `build_sim.cmd` 重新编译，页面切到固件模式即可验证。

### 改参数

`sim/core/cdpr_params.json`（唯一参数源），详见 [参数表.md](参数表.md)。

## 六、自检

```powershell
node sim/core/check_mechanics.mjs     # 力学：11 个位姿张力可行 + 正运动学 + 秩
node sim/core/sweep.mjs               # 鲁棒性：不同 dt / 轨迹幅度
node sim/test/compare_core.mjs        # C 核心与 JS 核心逐项对比
```

三条都通过（退出码 0）才说明模型是自洽的。

## 七、常见问题

**Q：三维视图是黑的？**
检查浏览器控制台是否有报错。渲染器是 Canvas2D 软件实现，不依赖 WebGL，
一般不会有兼容问题；如果窗口很小（< 200 px）会因尺寸为 0 而跳过绘制，放大即可。

**Q：HUD 显示「不可行」？**
说明当前位姿下 8 根绳无法同时受拉维持平衡。常见原因：
1. 平台跑出了工作空间（看 `x/y/z` 是否超出 ±0.15 m）；
2. 姿态角太大（`r/p` 超过 ±0.35 rad）；
3. 参数被改坏（卷筒高度、`point_shift`）——重跑 `check_mechanics.mjs` 确认。

**Q：固件模式启动失败？**
先确认 `firmware/build/board_sim.exe` 存在；不存在就按 §四 编译。
编译报「无法打开文件 board_sim.exe」说明进程还在运行，先在页面切回 JS 模式再编译。

**Q：帧率低？**
软件渲染在 1.3 万三角形规模下约 30~60 fps。可以关掉「框架」或「绳索」显示提速。

**Q：想让平台动得更快/更稳？**
改 `controller.max_trans_vel` / `max_trans_acc` / `tension_kp`，
然后用圆轨迹观察跟踪误差与张力波动。
