本文件说明 `sim/core/cdpr_params.json` 里每个参数的物理含义、默认值与来源，以及拿到实物后应该怎么改。

### 1.1 上夹层板的四角缺口（`frames.deck_hi_notch`）

上组锚点 `upper_y = 1.10 m` **高于**上夹层板面 `deck_hi_y = 0.985 m`，
所以上组 4 根绳从四角锚点斜向下走向平台四角时，必然穿过 `y = 0.985` 这一平面。
实测（SolidWorks 原装配体里上组滑轮在 0.928 m，位于板下方，本来不穿模；是我们把锚点抬到 1.10 m 之后才出现）。

处理办法是给上板**四个角各切一块方形缺口**，板面变成十字形：

```
      ┌──────────┬──────────┐      n = deck_hi_notch（默认 0.18 m）
      │░░░░░░░░░░│░░░░░░░░░░│      板半宽 0.4942 m
      │░░░░░░░░░░│░░░░░░░░░░│
      ├──────────┼──────────┤      ░ = 被切掉的角
      │          │          │          （|x| > n 且 |z| > n）
      │          │          │
      ├──────────┼──────────┤
      │░░░░░░░░░░│░░░░░░░░░░│
      │░░░░░░░░░░│░░░░░░░░░░│
      └──────────┴──────────┘
```

缺口尺寸是扫出来的，不是估的：对 8831 组位姿采样（x/z ∈ ±0.15、y ∈ 0.40~0.88、rpy ∈ ±0.2 / ±0.25），
取其中 1467 组「力学可行」的，算出上组 4 根绳与 `y = 0.985` 平面的全部交点（5868 个），
再看这些点的 `min(|x|,|z|)`（最小的那个决定缺口要开多大）：

| 姿态高度上限 | 交点 `min(|x|,|z|)` 的最小值 | 结论 |
| --- | --- | --- |
| y ≤ 0.68 m（日常作业） | 0.3271 | 缺口 0.33 就够 |
| y ≤ 0.72 m | 0.3074 | 缺口 0.31 就够 |
| 全范围（含 y = 0.88 极限） | 0.1915 | 缺口 0.20 才够 |

默认值取 **0.18 m**：四角各空出 0.314 m × 0.314 m（半宽 0.4942 − 0.18），
上述 8831 组位姿、5868 个交点**没有一个**落在缺口之外。
反过来，若把缺口设成 `0`（就是原来的整块板），5868 个交点全在板内 → 全穿模。
另一种彻底不谈缺口的做法是把 `deck_hi_y` 抬到 `1.18`（顶梁高度）当顶盖，
或干脆不显示上板（参考样机 BV1fk4y1m7uC 就只有一块底板）。

> 缺口只影响渲染：`web/scene.js` 用它决定画几个盒子。力学完全不看 `frames`。

> **`frames` 只影响外观**：外框尺寸、型材表、夹层板都只用于三维渲染；
> 决定绳拓扑与力学的是 `winders` 和 `platform`。把 `frames` 换成 SolidWorks
> 实测值后，可行位姿数完全不变（已验证）。
> 若改的是 `platform` 或 `winders`，必须重跑 `node sim/core/check_mechanics.mjs`。

> **`upper_y` / `lower_y` 不要随便改**：平台工作高度必须落在两者之间，
> 否则上下绳都只能向上拉（或都向下），6 自由度力封闭立刻失效。详见 README §5。
>
> **`edge_offset` 的作用**：把同一水平位置上的上/下两台电机沿边错开，避免两个锚点重合；
> 太小会让力矩行接近退化，太大会让张力分布变差。0.04 m 是数值搜索得到的折中值。

### 系绳点：两套拓扑

`winders.topology` 决定绳怎么接：

**`"corner"`（当前，按 SolidWorks 模型）** —— 平台共 8 个系绳点，就是**四个角 × 上下表面**：

```
角点 j = (sx, sz) ∈ {(+,+), (+,−), (−,−), (−,+)}
上绳 i = 2j    接 (sx·hx, +t0/2, sz·hz)   ← 板上表面
下绳 i = 2j+1  接 (sx·hx, −t0/2, sz·hz)   ← 板下表面
t0 = winders.tether_offset = 0.03 m
```

锚点在框架四角 `(±0.485, upper_y 或 lower_y, ±0.485)`，与系绳点在俯视图上**同方位**，
所以绳体是四条竖直棱上的「八」字，俯视图上**不跨对角、不交叉**。

代价：平台居中时 `A` 的 `My` 行恒为 0（绕竖直轴的力矩被四方向精确抵消），
`tilt_y` / `corner` 两个位姿不可行。详见 README §5。

**`"edge"`（备选）** —— 平台 8 个系绳点是**每条边 2 个角点**：上绳接该边一个角点的上表面、
下绳接该边另一个角点的下表面；锚点在四边中点（法向 `half_spacing`）。
上下两绳的力臂方向不同，`A` 的力矩行满秩，11 个位姿全部可行。

## 3. 绳索

| 参数 | 默认 | 单位 | 说明 |
| --- | --- | --- | --- |
| `cables.diameter` | 0.0015 | m | 钢丝绳直径（φ1.5） |
| `cables.emodulus` | 1.0e9 | Pa | 等效弹性模量（含编织绳折减） |

这就是控制器里「弹性预补偿」要补的量。

## 4. 执行器（86 闭环步进 + HBS860H + 减速器 + 卷筒）

| 参数 | 默认 | 单位 | 说明 | 拿到实物后 |
| --- | --- | --- | --- | --- |
| `actuators.hold_torque` | 12.0 | N·m | 86 闭环步进保持转矩 | 按电机铭牌 |
| `actuators.step_angle_deg` | 1.8 | ° | 步距角（两相混合式） | 一般不改 |
| `actuators.driver_microstep` | 16 | — | HBS860H 拨码细分 | **按实际拨码** |
| `actuators.encoder_counts_per_rev` | 10000 | — | 编码器线数 | 按电机规格 |
| `actuators.gear_ratio` | 10.0 | — | 减速比 | **⚠️ 型号未定，必须改** |
| `actuators.gear_efficiency` | 0.85 | — | 减速器效率 | 行星减速器 0.9~0.97 |
| `actuators.current_limit` | 7.3 | A | 驱动器最大相电流 | HBS860H 档位 |
| `actuators.torque_constant` | 1.65 | N·m/A | 电流-转矩系数 | 由保持转矩/额定电流 |
| `actuators.bus_voltage` | 48 | V | 母线电压 | 电源配置 |

### 由参数推出的关键指标

```
卷筒侧可用转矩  = hold_torque × gear_ratio × efficiency
单绳最大张力    = 上式 / drum_radius
卷筒每转绳长    = 2π/G × r
单步分辨率      = (2π / (360/step_angle × microstep)) / G × r
编码器分辨率    = (2π / encoder_counts) / G × r
```

默认值下：

| 指标 | 数值 |
| --- | --- |
| 卷筒侧可用转矩 | 102 N·m |
| 单绳最大张力 | 5100 N |
| 卷筒每转绳长 | 12.57 mm |
| 单步分辨率 | 3.93 µm |
| 编码器分辨率 | 1.26 µm |
| 0.45 m/s 时电机转速 | 2149 r/min |

> 单绳 5100 N 远超实际需要（40 N 量级），说明**电机能力非常充裕**。
> 真正限制性能的是减速器背隙、绳的弹性，以及控制周期。

### 5.1 任务空间 PID（`controller.pid`）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `enable` | `false` | 默认关闭，理由见下 |
| `d_filter_hz` | 8 | 微分项一阶低通截止频率 |
| `force_limit_ratio` | 0.8 | 平移输出上限 = 0.8·m·g = 31.4 N |
| `moment_limit_ratio` | 0.8 | 姿态输出上限 = 0.8·m·g·0.15 = 4.71 N·m |
| `trans.kp/ki/kd` | 400 / 40 / 30 | 平移三轴增益（N/m, N/(m·s), N·s/m） |
| `rot.kp/ki/kd` | 6 / 1.2 / 0.8 | 姿态三轴增益（N·m/rad 等） |

PID 的输出直接叠加到期望合力/力矩 `w` 上，之后照常做张力分配。积分项带抗饱和
（输出饱和且误差同向推时冻结积分），微分项带低通。

**为什么默认关闭（实测数据，2 kHz 定步长）**

| 场景 | PID off | 最好的 PID 配置 |
| --- | --- | --- |
| 推开 40 mm 后恢复：收敛时间 / 稳态振荡峰峰 | **0.90 s / 0.01 mm** | 0.98 s / 0.03 mm |
| 稳态静差（+2 kg 未知质量；绳索刚度差 30%） | **0.00 mm** | 0.00 mm；`kp=400/kd=200` 反而过冲 −9.13 mm |
| 动态跟踪峰值误差（1× 速度） | **42.3 mm** | 42.0 mm |

- 增益越大越差：默认的 `400/40/30` 把这组推开恢复恶化到 **1.68 s / 1.00 mm 振荡**。
  纯 D（`kp=0/ki=0/kd=80`）会直接发散，末态偏 32.75 mm。
- 原因是现有绳长环已经是硬位姿环：`l_ref = l(q_ref) − T_ref/k` 的弹性预补偿把张力
  分布翻译成绳长偏置，绳索等效刚度约 5 kN/m，静差天然为 0，再加 PID 只会引入相位滞后。
- 42 mm 的动态滞后来自轨迹加速段本身，与控制精度无关：把 `lref_vmax` 从 0.675 提到 5.0
  误差仍是 42.3 mm；`tension_kp` 设 0 为 42.7 mm；刚度 ×100 为 45.5 mm；阻尼 4→120
  反而恶化到 77.6 mm。要降低只能放慢轨迹或提高执行器加速度上限。
- 保留这个功能是为了接真机（真机有摩擦/蠕变/未建模动力学）与教学对比演示。

### 7.1 多点序列（界面「目标坐标」面板）

界面输入的路径点走 `Trajectory.moveSeq(pts, opts)`，每段时长自动算，不用手填：

```
aMax = max_trans_acc × 0.5        = 0.6 m/s²
vMax = max_trans_vel × 0.6        = 0.27 m/s
wMax = max_ang_acc × 0.5          = 3.0 rad/s²
wvMax = max_ang_vel × 0.6         = 0.6 rad/s
t_seg = max(√(5.77·d/aMax), 1.875·d/vMax, 0.2) / speed
```

`d` 段长取平移 3 轴与姿态 3 轴各自变化量的最大值（两者取大，保证同时满足）。
`speed` 是界面滑块（0.3~2.5×），1× 即满足上表的加速度限制。

- 与 §2.1 的演示序列不同，`moveSeq` **不强制 pitch=0**，6 个自由度全保留。
- 序列走完自动进入 `hold`；勾选「循环」则回到第一个点继续。

## 8. 改参数的推荐顺序

1. **先改几何**（框架、卷筒位置、平台尺寸）→ 跑 `node sim/core/check_mechanics.mjs`，
   确认可行位姿数不下降（`corner` 拓扑下 9/11 是上限，`edge` 拓扑下 11/11）；
2. **再改执行器**（减速比、卷筒半径、细分）→ 看 `summary` 里的分辨率与最大张力是否合理；
3. **最后调控制**（`tension_kp`、速度/加速度上限）→ 用圆轨迹看跟踪误差与张力波动；
4. 全部满意后 `python tools/gen_params.py` 生成固件参数头。
