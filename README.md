# 8 绳冗余绳驱并联机器人仿真平台

面向 **STM32F407ZGT6 + 86 闭环步进电机 + HBS860H 驱动器 + 减速器 + 卷筒** 的八绳冗余六自由度绳驱并联机器人（CDPR）仿真平台。外框几何按工作区 `新框架/新装配体.SLDASM` 的 SolidWorks 实测尺寸搭建：1.03 × 1.03 × 1.33 m 的 30×30 铝型材框架（44 根，含 16 根 45° 斜撑）、两块 988×988×10 mm 夹层板、上下两层 4 台电机、8 个角滑轮、动平台。

平台有两套可切换的「大脑」，共用同一份参数与同一套物理：

| 模式 | 说明 |
| --- | --- |
| **JS 仿真** | 浏览器内 2 kHz 物理 + 1 kHz 控制器，改代码立即生效，用于快速调参与看现象 |
| **STM32 固件 · 无板仿真** | `firmware/` 里的 C 代码（将来直接烧到 F407）在 PC 上编译运行，页面通过 WebSocket 读取它的输出 |

# 2) 浏览器打开
#    http://127.0.0.1:18000/web/index.html

## 2. 界面说明

- **三维视图**：鼠标左键旋转、Shift+左键或右键平移、滚轮缩放；右上角有等轴/正面/侧面/俯视预设视角。
  - 绳索按**张力着色**（蓝=低、绿=中、红=高），可切换单色
  - 青色线框 = 目标位姿；橙色板 = 实际动平台
  - 勾选「张力矢量」可显示每根绳的拉力方向与相对大小
- **左上 HUD**：实时位姿、目标位姿、力封闭判定（`Tmin` 是当前最小绳张力，出现 0 就说明有绳松弛）
- **右侧面板**
  - 运行：暂停/复位/仿真倍率
  - 运动控制：11 个预设位姿、圆轨迹、码垛、附加负载
  - **视频演示**：5 组预编排动作，对应参考样机的运动（见 §2.1）
  - **目标坐标（规划）**：手输 x/y/z/roll/pitch/yaw，可「移动到此点」或加入路径点列表做
    多点序列（见 §2.2）
  - **任务空间 PID**：可选闭环增益（默认关闭，见 §2.3）
  - 张力分配：4 种分配算法可切换（见 §4）
  - 显示：框架/绳索/目标/张力矢量开关
  - 控制台：所有事件日志（含固件输出）
- **底部**：8 根绳的张力曲线、绳长曲线，以及状态表（张力、目标、绳长、卷筒脉冲、转速、电流、状态）

### 2.1 视频演示序列

参数文件里的 `demos` 段定义 5 组关键帧动作，界面上「视频演示」一排按钮即可播放：

| 按钮 | 序列名 | 内容 | 时长 |
| --- | --- | --- | --- |
| 平移巡游 | `translate` | 框架内方形绕行 + 升降，验证三维平移 | 17.1 s |
| 姿态演示 | `attitude` | 横滚 ±0.10 rad、偏航 ±0.35 rad、姿态+平移组合 | 16.5 s |
| 圆周运动 | `circle` | 圆周轨迹叠加偏航姿态 | 10.0 s |
| 快速往返 | `fast` | 快速直线往返（考验加减速） | 4.6 s |
| 抛接动作 | `toss` | 竖直大幅抛接，对应视频 2 的高速抛接 | 5.4 s |

序列由关键帧 + 五次多项式平滑插值驱动，有两条硬约束：

1. **俯仰（pitch）恒为 0** —— 严格 8 角拓扑下该自由度几何不可控（见 §5），
   序列里即使写了 pitch 也会被强制归零，保证演示全程张力可行。
2. **段时长必须满足运动学限制** —— 峰值速度 `1.875·d/T ≤ max_trans_vel`、
   峰值加速度 `5.77·d/T² ≤ max_trans_acc`。下落段还要额外加长（绳只能拉不能推，
   放绳比收绳慢）。违反这两条，轨迹会被限速截断，平台追不上目标，出现明显滞后。

静态检查（每一帧的张力可行性）由 `node sim/core/check_mechanics.mjs` 覆盖；
动态跟踪质量可用演示时的 HUD 位姿与目标位姿对比观察。

### 2.2 输入坐标与多点序列

「目标坐标（规划）」面板可以直接输入 6 个自由度（`x/y/z` 单位 m，`roll/pitch/yaw` 单位 rad）：

- **移动到此点**：单点平滑插值过去。段时长自动按运动学限制算，
  不用手填（`t = max(√(5.77·d/a_max), 1.875·d/v_max, 0.2) / speed`）。
- **加入路径点 / 运行路径**：把一串坐标连成序列依次走。面板里的「速度」滑块
  （0.3~2.5×）直接缩放每一段的时长，1× 是满足加速度限制的最小时间。
- 序列走完自动进入 `hold`，停在最后一个点上。

底层是 `Trajectory.moveSeq(pts, opts)`，每段用五次多项式 `smoothstep5`
从**上一段终点**插值到本段终点。姿态三轴与平移同时插值，不做 pitch 归零
（这与 §2.1 的演示序列不同，演示序列为了保张力可行性才强制 pitch=0）。

### 2.3 任务空间 PID（默认关闭）

`sim/core/pid.js` 提供 6 轴 PID：输出直接叠加到期望合力/力矩 `w` 上，
再交给张力分配器分给 8 根绳。参数在 `controller.pid`：

| 键 | 值 | 说明 |
| --- | --- | --- |
| `enable` | `false` | 默认关闭 |
| `trans` / `rot` | `kp/ki/kd` | 平移与姿态两组独立增益 |
| `force_limit_ratio` | 0.8 | 输出上限 = 0.8·m·g = 31.4 N |
| `moment_limit_ratio` | 0.8 | 输出上限 = 0.8·m·g·0.15 = 4.71 N·m |
| `d_filter_hz` | 8 | 微分项一阶低通截止频率 |

**实测结论：在这个仿真里 PID 帮不上忙，建议保持关闭。** 三组实验（2 kHz 定步长）：

| 实验 | PID off | 最好的 PID 配置 |
| --- | --- | --- |
| 推开 40 mm 后恢复（收敛时间 / 振荡峰峰） | **0.90 s / 0.01 mm** | 0.98 s / 0.03 mm（增益越大越差，默认 400/40/30 是 1.68 s / 1.00 mm） |
| 稳态精度（+2 kg 未知质量、绳索刚度差 30%） | **静差 0.00 mm** | 同样 0.00 mm，只有 `kp=400/kd=200` 反而过冲 −9.13 mm |
| 动态跟踪峰值误差（1× 速度） | **42.3 mm** | 42.0 mm（几乎无改善） |

原因有两个：

1. **现有绳长环本身就是一个很硬的位姿环。** 控制器下发的绳长指令是
   `l_ref = l(q_ref) − T_ref/k`，其中弹性预补偿项 `−T_ref/k` 把张力分布直接翻译成绳长偏置。
   绳索本身刚度极大（等效弹簧刚度约 5 kN/m），平台被这套"虚拟弹簧"牢牢拽在
   目标位上，静差天然为 0。再加一层 PID 只是串了一个多余的环，只会引入相位滞后。
2. **动态滞后的真正来源是轨迹本身，不是控制精度。** 42 mm 的峰值误差出现在
   五次多项式加速段的起点（`t≈1.7 s` 与 `t≈2.8 s`），平台追不上目标。
   改 `lref_vmax`（0.675→5.0）误差纹丝不动仍是 42.3 mm；改 `tension_kp`
   （8e-5→4e-4 或直接设 0）为 42.9/42.7 mm；改绳索刚度（×100）为 45.5 mm；
   改阻尼（4→120）反而恶化到 77.6 mm。要降低它只能**放慢轨迹**或**加大执行器加速度上限**。

所以面板里保留 PID 是为了两种场合：一是接真实硬件（真机有摩擦、有绳索蠕变、
有未建模的动力学，那时位置环不会这么理想）；二是教学演示，可以现场对比开/关的差别。

### 电机位置 ≠ 锚点位置（重要）

`winders.topology: "corner"` 时，8 台电机画在框架的 **8 个角**（4 角 × 上下两层），
绳的锚点也在同一个角、同一水平半径（`corner_spacing = 0.485 m`）。

**电机安装高度与锚点高度可以分开**（例如电机想藏进底座，但锚点要留在高处）：

| 参数 | 含义 | 当前值 |
| --- | --- | --- |
| `winders.upper_y` / `lower_y` | **锚点**高度（参与力学） | 1.10 / 0.10 m |
| `winders.motor_upper_y` / `motor_lower_y` | **电机**安装高度（仅外观） | 1.10 / 0.10 m |

当前上组 4 台电机在框架顶部（y = 1.10 m），下组 4 台装在**框架底部**（y = 0.10 m），
两组锚点与电机同高；平台工作高度 0.60 m 落在两者之间：上组绳往上拉、下组绳往下拉，
构成双向力封闭的八字形。

**关键约束**：两组锚点必须分居平台工作高度两侧，且离平台越远越好。
实测扫描（`lower_y` 变化，`upper_y` 固定 1.10，平台 0.60）：

| `lower_y` | 可行位姿 | 失效的位姿 |
| --- | --- | --- |
| 0.05 / 0.10 / 0.20 | **9/11** | `tilt_y`、`corner`（角点拓扑固有的 `My` 退化） |
| 0.30 / 0.40 | 8/11 | 再加 `yaw` |
| 0.50 / 0.55 | 7/11 | 再加 `tilt_x` |
| 0.60 及以上 | 3/11 | 除 `home`/`up`/`down` 外全失效 |

也就是说下组锚点抬到平台高度附近时，下组绳几乎水平，`A` 的力矩行塌掉，
连纯平移都会失败 —— 所以下组锚点必须留在框架底部，不能跟着电机往上装。

> ⚠️ **减速比务必按实际型号改**：它同时影响可达绳速、最大张力和定位分辨率。
> 参数文件里 `actuators.gear_ratio` 一处修改，全平台（JS 仿真、固件、曲线、状态表）同步。

### 上夹层板为什么要开四角缺口

上组锚点在 y = 1.10 m，上夹层板面在 y = 0.985 m —— 锚点比板还高，
所以上组 4 根绳必须从上往下穿过这块板。SolidWorks 原装配体没有这个问题
（上组滑轮装在 0.928 m，在板下方），是后来把锚点抬到 1.10 m 才出现的。

解决办法是给上板**四个角各切掉一块方形**，板面成十字形：

- 新增参数 `frames.deck_hi_notch`（默认 **0.18 m**），表示缺口半宽；
- 缺口形状是直角方形（`|x| > n` **且** `|z| > n` 的区域被切掉）；
- 尺寸是扫出来的：8831 组位姿采样里 1467 组力学可行，上组绳与 y = 0.985 平面
  有 5868 个交点，其 `min(|x|,|z|)` 最小 0.1915（全范围）/ 0.3271（y ≤ 0.68 日常作业）；
  取 0.18 后这些交点全部落在缺口内。**斜切（45°）实测更差**，必须用直角缺口。
- 设成 `0` 就退回整块板（会穿模，仅用于对照）。

> 缺口只影响渲染（`web/scene.js`），力学完全不看 `frames`。
> 若不想开缺口，也可以把 `deck_hi_y` 抬到 1.18（当顶盖）或干脆不画上板。

## 4. 张力分配（8 绳冗余的核心）

`allocateT(model, x, wrench, {mode})` 支持 4 种模式，界面「张力分配」下拉可切换：

| mode | 名称 | 说明 |
| --- | --- | --- |
| 0 | 无张力 | 自检用，绳张力全 0 |
| 1 | 最小范数解 | `min‖T‖ s.t. A·T = w`，数学上精确但不保证 T≥0 |
| **2** | **非负最小二乘（默认）** | `min‖A·T − w‖² s.t. T≥0`，投影梯度，残差通常 <0.1 N |
| 3 | 神经启发式 | 最小范数解 + 拉对内部对抗预紧（对照用） |

其中 `w = A·T` 是「平台作用于绳的等效力」，锁定平衡时 `w = +m·g·e_y − F_contact`。

### 符号约定（与论文/教材一致）

```
u_i = A_i − B_i      由平台系绳点指向卷筒
s_i = u_i / l_i      单位方向
绳对平台的拉力      F_i = T_i · s_i
结构矩阵            A_i = [ s_i ; (B_i − p) × s_i ]
静力平衡            w = A(q)·T
```

## 5. 拓扑与「为什么这样布置」

八绳冗余 6 自由度要能同时控制 **平移 + 姿态**，结构矩阵 `A`（6×8）必须满秩，
且力旋量锥要覆盖重力方向。参数里用 `winders.topology` 选择布置方式，当前是
**`"corner"`（严格 8 角，按你的 SolidWorks 模型）**：

| `topology` | 锚点位置 | 系绳点 | 11 位姿可行数 |
| --- | --- | --- | --- |
| **`"corner"`（当前）** | 框架 8 角，`(±0.485, 1.10 或 0.10, ±0.485)` | 平台 4 角 × 上下表面（`tether_offset` 分开） | **9/11** |
| `"edge"`（备选） | 四边中点，法向 0.325 m | 每边两个角点 | 11/11 |

### 严格 8 角拓扑的已知限制（必须知道）

**`A` 的第 5 行 `My` 在平台居中时恒为 0。**

`My = dz·sx − dx·sz` 只用到水平坐标。方形平台上，四个方向的力臂两两相反且等长，
绕竖直轴的力矩精确抵消 —— 实测 `My` 全行最大值 **0.00e+0**，`rank(A) = 5`。

后果：

- 纯**俯仰**（`tilt_y`）与 `corner` 两个预设位姿**必然不可行**（9/11 里的 2 个失败就是它们）；
- 平台一旦离开中心，`My` 才重新非零（`x=0.05` → 1.14e-2，`x=0.07` → 1.61e-2），
  但比横滚/偏航的 1.04e-1 仍小 5~25 倍，俯仰只是「勉强能动」；
- 平移、升降、横滚、偏航都正常，**不影响圆周运动、码垛、演示序列**。

要 6 自由度全可控，只有换几何：把 `topology` 改成 `"edge"`（锚点回四边中点），
或把平台改成矩形（实测 `half_size_x/z = 0.15/0.25` 时 `My` 升到 9.47e-2、rank 恢复 6）。
这两条都会**偏离你的实体模型**，所以当前没有采用。

> **外观与运动学是分开的**：`frames`（外框型材表、夹层板、外廓尺寸）只影响三维外观；
> 决定绳拓扑与力学的是 `winders` 和 `platform`。所以换外框不需要重做拓扑搜索 ——
> 把 `frames` 换成 SolidWorks 实测值后，可行位姿数完全不变（已验证）。
> 反之若改动 `platform` 或 `winders`，必须重跑
> `node sim/core/check_mechanics.mjs` 确认可行位姿数没有下降。

### 力封闭的充要条件（尺度无关的判据）

`A` 的零空间里存在一个**严格正**的向量 `z > 0`，才能沿它把 8 根绳同时绷紧
（`A·z = 0` 不破坏力平衡）；不存在则无论怎么分配，总有绳被压到 0。
代码里由 `findPositiveNullspace()`（JS）与 `positive_nullspace()`（C）实现，
失败时退化为「上组全撑、下组全 0」的解 —— 残差虽然为 0，但一半绳是松的。

这也是 `corner` 拓扑下 `feasible` 判据不能只看残差的原因：还要看最小张力。

## 8. 换成你的 STM32 硬件

1. **改参数**：`sim/core/cdpr_params.json` 里填实物的减速比、卷筒半径、框架尺寸；
2. **生成参数头**：`python tools/gen_params.py`（把 JSON 转成 `firmware/core/cdpr_params.h`）；
3. **接外设**：`firmware/stm32f407_port/stm32f407_port.c` 里按实际接线改 `kMotorPins`
   （PUL 用 TIM2/TIM5 的 PWM，DIR/ENA 用 GPIO），并实现编码器读取；
4. **控制中断**：在 TIM6 更新中断（1 kHz）里调用 `ctl_tick(&boot, &ctl, &traj)`；
5. **验证**：先在 PC 上跑 `board_sim.exe` 确认逻辑正确，再烧录。

> 建议顺序：先在「固件 · 无板仿真」里把轨迹和张力跑通，确认 `feasible=1` 且曲线正常，
> 再上真机。真机上第一件事是用很小的速度（`controller.max_trans_vel = 0.05`）做单绳收放测试。

## 9. 已知限制

- **严格 8 角拓扑不是 6 自由度全可控**：`A` 的 `My` 行在平台居中时恒为 0，
  纯俯仰（`tilt_y`）与 `corner` 位姿不可行。这是几何决定的，调参数无解；
  要 6 自由度请用 `topology: "edge"` 或把平台改成矩形。详见 §5。
- **上夹层板必须开四角缺口**：上锚点 1.10 m 高于板面 0.985 m，上组绳必然穿板；
  `frames.deck_hi_notch = 0.18` 把四角切掉。设成 0 会穿模。详见 §3。
- **`rpy` 三个分量的命名与 Y-up 世界系错位**：`rpy[0]`/`rpy[1]`/`rpy[2]` 走的是
  ZYX 欧拉角（Z-up 习惯），在本项目 Y 轴朝上的世界系里，`rpy[1]` 实际是**绕竖直轴自转**
  （板不倾斜），`rpy[2]` 才是真正的倾斜。所以「圆轨迹」按钮里 `roll_amplitude` /
  `yaw_amplitude` 都会让板明显倾斜，而 `pitch_amplitude` 不会。
  纯平移圆周时残余的 1~2° 倾斜来自关键帧折线的加速度尖峰激励弱刚度姿态自由度，
  段数加密（12 → 120）可降到 0.035°。
- **没有真实张力传感器**：`ctl_tick` 里 `read_tension` 返回 0 时，控制器退化为纯位置 + 力矩前馈；
  装了拉力传感器（或通过 HBS860H 的电流估算张力）后张力闭环才真正生效。
- **摩擦未建模**：卷筒/滑轮的库仑摩擦、绳与滑轮的接触都简化为结构阻尼，长时间运行会有少量漂移。
- **减速器参数待定**：`gear_ratio` 暂按 10 估算，实际选型后必须更新。
- **渲染是软件实现**：Canvas2D 画家算法，无 WebGL 依赖。当前场景约 **4.1k 三角形**
  （框架 528 + 电机 2048 + 平台 60），经下述优化后稳定 60 fps 满帧
  （浏览器 rAF 上限即是 60；实测 HUD 显示 240，那是多次 rAF 回调的平均值口径）。
  若要更大场景可换 WebGL2（渲染器接口已隔离）。

  **帧率优化的三处改动**（`web/renderer.js` / `web/scene.js`）：
  1. **静态几何离屏缓存** `Renderer.drawStatic(meshes, camera)`：框架与 8 个电机在
     世界坐标里永不动，却原本每帧用 identity 矩阵重投影 + 剔除 + 光照 + 深度排序
     （约 2.6k 三角形），纯属浪费。现在一次性光栅化到离屏 canvas，相机不变时直接
     `drawImage` 整图贴回；每帧只重绘会动的动平台（60 三角形）和绳索线段。
     缓存键 = `view + proj + 画布像素尺寸`，**旋转/缩放视角时才重建一次**。
  2. **圆柱分段 20 → 12**（滑轮 14 → 10）：单电机三角形数 448 → 256，8 台共省 1536 个。
  3. **DPR 上限 2 → 1.5**：软件光栅化是 CPU 填充，像素数随 dpr² 增长，填充量少约 44%。

  实测（Edge headless，1600×1000）：优化前画面 84 fps → 优化后 **240 fps**
  （同一 rAF 计数口径）；拖动旋转视角时仍有 38.7 fps（此时缓存每帧重建，属最坏情况）。
